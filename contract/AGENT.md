# 前端 Agent 工作规范

开始前端开发前，必须阅读本文件、`FRONTEND.md` 以及项目自身的 `AGENTS.md`。

- 使用项目指定的 Node.js 24 LTS 运行时；不得擅自降低版本要求或改用未验证的新大版本。
- 默认使用简体中文撰写文档、用户界面文案、操作说明、验收报告和与用户的沟通；代码标识符与外部 API 保持兼容。
- 遵守项目业务要求，保留既有 API 契约；开发环境只保留项目指定域名对应的唯一前端服务。
- 设计或修改路由时必须遵循 FRONTEND.md 与 INTERACTION.md 的 URL 约定：Path 描述页面/资源/业务层级，过滤器等查询条件放 Query；提交前按 ACCEPTANCE.md 做语义 Review 和行为验收。
- 未经批准，不得引入 SSR、重复开发通用组件、伪造生产数据、随意发明路由或堆叠样式补丁。
- 给业务组件取明确的名称；React + Vite 项目在开发模式提供点选元素定位源码文件/行号的能力，支持将定位信息交给 Agent；正式构建禁止包含该功能。
- 交付前执行项目已有的契约检查、浏览器验收和必要的视觉复核。
- 交付报告必须用中文明确列出：实际检查结果、失败或未验证项、例外及遗留问题。

处理数据表格、财务数据或测量指标时，必须阅读 `DATA-DISPLAY.md`，确保表头与数据列对齐、金额保留两位小数、数值格式和业务精度一致。

开发和验收前还必须阅读 `INTERACTION.md` 和 `ACCEPTANCE.md`；不允许把未运行的浏览器测试、视觉检查或业务边界测试报告为通过。

组件库决策：默认使用 MUI；高灵活度页面可经明确判断使用 shadcn/ui；不引入 Ant Design。不得擅自混用多套基础组件体系。
