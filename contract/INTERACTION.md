# 专业软件交互与状态规范

## 数据表格
- 表格优先支持查找、比较、查看或操作记录的核心任务；首列优先使用人能识别的记录名称，不以内部 ID 代替。
- 筛选条件必须可见，支持一键清除；排序必须基于原始类型值，不能对格式化后的字符串排序。排序方向应明确标示。
- 数据量大时合理使用分页、虚拟滚动、固定表头或首列；避免无条件渲染全部数据。横向滚动不得造成表头与内容错位。
- 同一列的表头、单元格、占位符共享列定义和对齐规则。遵循 DATA-DISPLAY.md。
- 表格应使用语义化 HTML；只有真正需要单元格级键盘导航时才使用 ARIA grid，并实现相应焦点管理。排序状态应可供辅助技术识别。

## 筛选、导航与状态
- 可以分享或恢复的筛选、排序、分页、选中记录应优先放入 URL；临时交互状态留在组件内。
- 筛选条件变化后，分页必须回到合理页码；明确区分“无数据”和“当前筛选无结果”。
- 详情页返回列表时尽可能恢复筛选、排序和滚动位置。
- 页面必须支持直接访问、刷新、浏览器历史记录与未知路径提示。

## 表单与操作反馈
- 字段具有明确标签、单位、必填标记和可理解的校验错误；错误尽量定位到具体字段。
- 提交中防止重复提交；成功、失败和部分成功分别反馈，不得在服务器确认前宣称成功。
- 破坏性操作明确对象与后果，必要时二次确认；有可行的撤销机制时优先提供撤销。
- 耗时操作应显示进行状态；可恢复的网络失败提供重试入口，避免直接丢失用户输入。
- 保存未完成的数据时应考虑离开页面的提醒，避免静默丢失。

## 图表与比较
- 坐标轴、图例、单位、时间范围和数据来源必须明确；不得用颜色作为唯一的状态信号。
- 同一指标的比较必须使用一致单位、精度与可比较的轴尺度；若采用截断坐标轴，应显式提示。
- 缺失值不得伪装为零；关键图表提供可读的文字摘要或数据表替代。
- 数据更新应清晰标示加载、失败和最近更新时间（适用时）。

## 布局与性能
- 主要操作区域在项目约定的屏幕宽度下不得被裁切；弹窗、表格和侧边栏应有明确滚动策略。
- 异步加载应尽量预留空间，减少布局跳动；不要以整页闪烁替代局部刷新。
- 大数据表、复杂图表、长列表优先测量性能瓶颈，再选择虚拟化、懒加载或计算缓存。
- 交互响应、主要内容加载和视觉稳定性应参照 Core Web Vitals 指标进行实测，不凭主观感觉宣称性能达标。

## 可访问性
- 优先使用原生语义元素，按钮是按钮、链接是链接；键盘焦点必须可见。
- 弹窗需要正确管理焦点和关闭行为；错误提示与状态变化应能被辅助技术感知。
- 颜色对比度、字号和点击目标尺寸遵循适用的 WCAG 要求；不得只依靠红绿区分状态。
